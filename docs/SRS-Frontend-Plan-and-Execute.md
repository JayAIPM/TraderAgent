# 需求规格说明书（SRS）
## 前端 Plan-and-Execute 功能迭代

---

## 1. 迭代概述

| 项 | 内容 |
|---|---|
| 迭代名称 | 前端 Plan-and-Execute 功能迭代 |
| 产品定位 | 优化前端交互体验，完整展示 Plan-and-Execute 三个阶段（规划/执行/聚合）的新特性 |
| 技术栈 | Vue 3 + TypeScript + Element Plus + Vite |
| 依赖后端 | 后端已支持 Plan-and-Execute，且完全向后兼容 |
| 目标用户 | 使用待办事项 AI 助手的所有用户 |

---

## 2. 现状分析

### 2.1 当前前端实现

**现有功能：**
- 简单的聊天界面
- 显示用户消息和 Agent 响应
- 待办事项列表（右侧面板）
- 消息发送后自动刷新列表

**交互流程：**
```
用户输入 → 发送请求 → 等待 → 显示单一结果 → 刷新列表
```

### 2.2 待改进的问题

| 问题 | 说明 |
|-----|------|
| 加载状态单一 | 只显示"思考中..."，无法区分规划/执行/聚合三个阶段 |
| 无法展示多步骤 | 后端现在支持一次执行多个 step，但前端只显示最终结果 |
| 无法看到执行细节 | 每个 step 的执行成功/失败状态不可见 |
| 缺乏执行追踪 | 无法看到哪些 step 成功、哪些失败 |

## 3. 功能规格

### 3.1 新特性列表

| 特性 | 说明 | 优先级 |
|-----|------|------|
| 阶段式加载动画 | 分阶段显示规划/执行/聚合的动画效果 | P0 |
| 多步骤执行结果展示 | 完整展示每个 step 的执行结果 | P0 |
| 详细结果卡片 | 每个 step 都有独立的结果展示（成功/失败） | P0 |
| 聚合消息优化 | 友好展示多个待办创建、多个操作等场景的结果 | P1 |
| 状态同步保持 | 执行完成后正确同步待办列表 | P0 |

### 3.2 阶段式加载动画

**规格要求：**
1. 发送消息后，立即进入第一个阶段
2. 三个阶段依次展示，每个阶段有对应的图标和文案
3. 阶段完成后显示"✓"标记

**阶段对应：**
```
阶段一：🎯 规划中... → 后端 Planner 执行
阶段二：⚡ 执行中... → 后端 Executor 执行
阶段三：📊 聚合中... → 后端 Aggregator 执行
```

**UI 设计：**
- 在聊天消息区域显示当前阶段
- 每个阶段有 1-3 秒的过渡动画（配合后端真实执行进度）
- 阶段之间平滑切换

---

### 3.3 多步骤执行结果展示

**规格要求：**

1. **整体结构：**
   - 显示完整的执行结果树
   - 总共有 X 个 step，成功 Y 个，失败 Z 个（X=Y+Z）
   - 底部显示聚合后的友好消息

2. **每个 step 展示：**
   ```
   [图标] 步骤描述 [状态]
   ├─ 输入参数（可选，折叠显示）
   └─ 执行结果（成功/失败详情）
   ```

3. **step 图标对应：**
   | 类型 | 图标 |
   |-----|------|
   | create | ✏️ |
   | update | 🔄 |
   | delete | 🗑️ |
   | query | 🔍 |
   | clear | 🚫 |
   | unknown | ❓ |

4. **状态指示：**
   | 状态 | 视觉标识 |
   |-----|---------|
   | 成功 | 绿色 ✓ + 浅绿色背景 |
   | 失败 | 红色 ✗ + 浅红色背景 |
   | 跳过 | 灰色 - |

---

### 3.4 详细结果卡片

**规格要求：**

1. **折叠/展开：**
   - 默认显示概要
   - 点击展开/折叠详细信息
   - 多个失败 step 自动展开以便排查问题

2. **失败详情展示：**
   - 完整的错误信息
   - 友好的错误提示文案
   - 可重试按钮（如果支持的话）

---

### 3.5 聚合消息优化

**规格要求：**

根据不同场景显示友好的聚合消息：

| 场景 | 示例消息 |
|-----|---------|
| 单条创建 | "已为您创建待办事项：...，时间：..." |
| 多条创建 | "已为您创建 X 条待办事项：\n1. ...\n2. ..." |
| 创建+更新 | "已完成 2 个操作：1. 创建... 2. 更新..." |
| 部分失败 | "已完成 X 个操作，失败 Y 个：...（失败详情）" |

## 4. 技术架构

### 4.1 响应数据结构

**新增后端返回字段：**

```typescript
// 后端返回结构（保持向后兼容）
interface AgentChatResponse {
  intent: 'create' | 'query' | 'delete' | 'clear' | 'update' | 'unknown'
  confidence: number
  action: string  // 聚合友好消息
  result?: SkillResult
  
  // 新增：Plan-and-Execute 详情（可选）
  planDetails?: {
    thought?: string
    steps: StepExecution[]
    summary: ExecutionSummary
  }
}

// Step 执行详情
interface StepExecution {
  id: string
  type: string
  description: string
  success: boolean
  message?: string
  data?: any
  error?: string
  references?: string[]
}

// 执行摘要
interface ExecutionSummary {
  total: number
  successful: number
  failed: number
  terminated: boolean
  terminatedAt?: string
}
```
